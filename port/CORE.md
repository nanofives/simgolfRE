# portsim core (phase 3.0, 2026-10-19)

The conventions every phase 3 module follows, and what the core provides. Read with port/README.md (rules),
port/test/README.md (how to add and test a function) and re/model/DECISIONS.md (pointer representation, U-0724).

## 1. Files

| file | what |
|---|---|
| `include/portsim/arith.h` | the original's integer arithmetic: wrapping `add32 sub32 mul32 neg32`, x86 shifts `shl32 sar32 shr32` (count mod 32), `div32 mod32 udiv32` (truncate toward zero, throw `DivideError` where `idiv` raises #DE), `abs32` (INT_MIN stays), `sx8 sx16 zx8 zx16`, `ftol_low32` (__ftol), `NoReturn` |
| `include/portsim/ptr.h`, `src/ptr.cpp` | `Ptr<T>` over the context's 32-bit virtual address space, GameState accessors `state_obj / state_arr / state_va / state_grid`, `Grid<T>`, the VC6 copy and string idioms `rep_movs vstrlen vstrcat vstrcpy vstrpbrk` |
| `include/portsim/registry.h` | `Ctx` (GameState + `Memory` + attached `ExeConstants` / `GameFiles`), `Ret`, `FuncDef`, `ModuleDef`, `DefectDef`, `SG_NEGCTL`, `SG_DEFECT`, `MissingResource` |
| `include/portsim/execonst.h`, `src/execonst.cpp`, `include/portsim/execonst_desc.inc` | `ExeConstants`: the user's own exe, constants by model descriptor name; the .inc is GENERATED by `re/tools/execonst_gen.py` from re/model/f_descriptors.tsv (offsets, sizes, types and sgh64 hashes only) |

| `test/test_core.py` | negative controls of every 3.0 function, defects, exe constants, game files |

## 2. Writing a port function

1. **State.** Take `Ctx &ctx`. Read and write GameState through named members. Use `ctx.gs().member` for a plain
   in-bounds access. Use a `Ptr` from `state_arr` / `state_obj` / `state_grid` wherever the original indexes without
   a bound check or follows a pointer: Ptr arithmetic wraps modulo 2^32 like the original's `lea`, so an index past the
   end reads the same neighbouring object of the image the original read, and an access outside every mapping throws
   `Fault` (SG_E_FAULT). Examples: `overlay_char_at` (a negative tile type reads g_holes below g_tileTypeAttrs, which
   the vectors exercise), `sin_scaled` (entry 256 = the dword after g_sinTable).
2. **Struct members** of model records: `(state_arr(ctx, &GameState::g_placed_objects) + i).field(&PlacedObject::x)`.
   `field` also takes an array member (element 0). Model structs are `#pragma pack(1)`.
3. **Pointers** are 32-bit virtual addresses (arguments, state words, returns). Make a `Ptr<T>(ctx.mem, va)` from an
   argument; return `ptr.va()`. Never cast a host pointer into state; never write an original address literal
   (test_static.py refuses literals in the exe and DLL image ranges).
4. **Arithmetic.** Every signed `+ - *` that can overflow in the original goes through arith.h, and so does
   every `<<` of a possibly negative value, every shift by a variable count, and every division by a variable.
   `x / 8` on an `int32_t` (cdq / and / add / sar in the original) is plain C++ `/`.
5. **Floating point.** Doubles with the x87 word 0x027f (53-bit, nearest): a single +, -, *, /, sqrt, and the CRT
   `sin` for initSinTable's arguments, equal the original on x64 SSE2. Declare `fpcw = 0x027F` in the FuncDef when the result goes
   through x87 code. Conversions to int are `ftol_low32`. Anything that depends on 80-bit intermediates or another
   control word needs explicit emulation (U-0721; 3.4 owns the shot x87 sites).
6. **Strings.** The original's literals sit in .data string pools, GameState objects of class `const`
   (`f_strpool_*`). Name a literal as (pool member, byte offset) and use the ptr.h string idioms on virtual
   addresses: `vstrcat(ctx.mem, state_va(ctx, &GameState::g_textBuffer), state_va(ctx, &GameState::f_strpool_4c4f98) + 0x288)`
   (text.cpp). The text itself never appears in port code.
7. **Loops the original cannot leave.** When the port can prove the original would spin forever from this state (a
   fixed point), throw `NoReturn{"<function>"}` (SG_E_NO_RETURN) instead of hanging the harness (decaySum,
   decaySum2). Do not invent bounds the original does not have.
8. **Calls between port functions** are plain C++ calls (`abs_diff` -> `fold_range` -> `sin_scaled`). A function
   another child needs goes in that child's or the core's header; declare it there with its spec comment.
9. **Registration.** Adapter + FuncDef row + negative-control switch in the module's `kFuncs`, module line in
   src/sim/modules.inc (port/test/README.md "Adding a function").

## 3. Defects (compatibility switches)

Decision 4: the port is bit-exact with the original including its defects. A defect that a fix would change is a
switch:

```cpp
namespace { int g_defect_sin_past_table = 1; }                 // 1 = behave like the original (default)
... if (index == 255 && !SG_DEFECT(g_defect_sin_past_table)) tb = ta;   // the fixed behaviour
const DefectDef kDefects[] = {{"sinScaled.readPastTable", "model_defects#10", "<one line>", &g_defect_sin_past_table}};
extern const ModuleDef kModule_util = {"util", kFuncs, nF, kDefects, nD};
```

- Name `<function>.<what>`, `ref` = the model_defects.md entry (`model_defects#N`). A defect you find that is not in
  model_defects.md: APPEND an entry there with the instructions as evidence, then register the switch.
- Process-wide flags. C ABI `sg_defect_count / _info_get / _set / _get / _reset`; Python `lib.defects()`,
  `lib.defect(name, on)`; the test fixture resets every switch to 1 after each test.
- Every switch has a test showing ON = GREEN on the vectors (or segments) and OFF changes exactly the inputs the
  defect affects (test_defect_sin_past_table).
- Out-of-range reads and writes the original does without a bound check (model_defects.md section 1) are reproduced by
  the address-space model itself (Ptr arithmetic). They get a switch only when a fix is wanted (phase 7).

Registered: `sinScaled.readPastTable` (model_defects#10).

## 4. Negative controls

Every ported function has `int g_negctl_<x> = 0;` read through `SG_NEGCTL`, with modes listed in the comment at the
top of its module, and an entry in test_core.py: `NEGCTL_RED` (the vectors must read RED) or `NEGCTL_BLIND` (a wrong
body the vectors cannot see, recorded on purpose: the segments must cover it). Do not keep a mode that is an
equivalent mutant (approxDistance's tie form was one: for a == b both forms give the same value). Blind spots found in 3.0:
decaySum's loop bound 0x41, tileType zero-extended (no negative type byte in the vectors), wallHeight's mask
zero-extended (needs dir >= 8 with a negative mask byte), objectAt extending type 7 (no type-7 object with a level
other than 1).

## 5. Exe constants and game files

**ExeConstants** (execonst.h). Startup: `sg_exe_load(path)` / `ExeConstants::load_file`. It verifies that `.data`'s
virtual size equals sizeof(GameState) and that every descriptor's bytes hash to the anchored exe's, and it refuses
any other file by naming the first descriptor that differs. Then:
- `ctx.exe().get<double>("f_k_dbl_4bba48", i)`, `bytes(name)`: any descriptor (`.rdata` scalars, IATs, pools, tables).
  initSinTable is the first client.
- `fill_state(gs, Fill::ConstObjects | Fill::InitialImage)` (`sg_exe_fill_state`): the GameState's initial values
  from the file's initialised .data (class `const` only, or the whole image as the loader maps it). Run-time tables
  in the bss are not in the file: g_sinTable comes from `init_sin_table`, g_tileTypeAttrs from the course loader.
- Port functions read `const`-class objects as GameState members. In vector tests those bytes come from the corpus
  seeds; test_exe_constants_equal_the_corpus_seeds shows they equal the exe's.
- Tests: `$SG_EXE_PATH`, else original/golf_clean.exe. Tests that need it skip when it is absent.

**GameFiles** (gamefiles.h): the story file, roster, string tables and course files reach the core ONLY as
`ctx.files().read_all("<logical name>")` / `size()` / `read()`. A logical name is the path relative to the
install root, case-insensitive, with `/` and `\` treated as the same. `MissingResource` when absent. The C ABI gives
each context a MemoryGameFiles (`sg_files_put / _clear / _size`) or a directory (`sg_files_root`). 3.5 (story file,
golfer roster) uses it first: the loader port reads bytes through this interface and parses them itself.
Formats are not part of the interface (phase 4).
