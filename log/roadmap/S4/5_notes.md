## Method

1. `5_convert.py --step S4.5 --module audio_seq --compile` converted the hook sources (c3an, c3ar, c3au, c3az, c3bd, c3bi, c3bn, c3ca, c3cf,
   c3cl, c3cx, c3dh, c3dj, c3do, c3dt, c3ew, c3ex, c3fd, c3fh, c3fk, c3fl, c3fn): 72 blocks, 8 refused (Midi_Device::openOutput,
   Seq_rewind, Midi_Device::flushMessages, Midi_scanTrack, Midi_Device::handleMetaEvent, Seq_getTrackFlagHigh, Midi_Device::emitEvent,
   Midi_seekTrackToTick: the converter cannot split a call with `reinterpret_cast<unsigned>(static_cast<char*>(self) + 0x3c)`, one
   `;` inside a macro, and one missing definition). The first compile had 100+ errors (memory pointers dereferenced as host pointers,
   `&local` passed to callees, function-pointer calls, `strcmp` on virtual addresses, the inline asm of buildPlayOrder).
2. Result: 40 blocks written by hand (hand1..3, from the hook source and the instructions, with the instruction addresses of the hook's
   comments), 8 of them the refused functions; 14 converted blocks patched (s5_patches.py); the other 26 kept as converted. Their provenance line
   says `converted from <hook source>` or `hand-fixed conversion of` / `written from`.
3. Port rules kept: every call outside the function goes through the dispatcher (snd_call by rva, snd_vcall by slot, snd_import); module
   globals through snd_va / snd_obj / snd_arr; wrapping arithmetic through arith.h (sub32, udiv32); no image-range literal (test_static found one in
   a comment, fixed). The node-list unlink shared by shutdown / drain / dispatch / updateChannel is one helper (`list_unlink`).
4. Locals the original passes by address (the out slot of Seq_listGetAt, the count slots, the tag / header slots of the MIDI loaders) live in
   16-byte cells (`fcell`, U-1440), one per function, because the functions call each other while their slots are live.

## Judge

- Oracle (decision G1): S4.1's fixture VM rebuilds each key, the original runs in Unicorn over the user's sound.dll, the port runs as the second
  arm on the same memory in layouts A / B / C; calls to code the port does not own reach the emulator as host calls. The 113 registry keys of the
  80 rows (all rows have a C3 path-1 key, no derived key needed): 1,840 vectors.
- Default replay (no emulator, no Node): bundles (port/corpus/audio, local) + golden digests, x64 and Win32.
- Negative controls: mode 1 of every function (a changed return, or one flipped dword the function owns); mode 2 of Seq_setTempo (every x87
  operation as a plain double operation).
- x87 (port/CORE.md section 7): Seq_setTempo ran in the C3 fixtures at 0x027f (key _w27f, 12 vectors) and 0x0f7f (key _wf7f, 12 vectors). On Win32 its body executes the
  original's x87 instructions (X80 helpers) under the word of the call.

## Findings (all from the C3 notes and this step's transcription; nothing was changed)

- Seq_getTrackFlagHigh returns the track count with its low byte zeroed for a rejected index (`xor al, al`) and Seq_listGetAt's code with the low byte replaced by the
  flag on the accepted path; the port keeps both (0x23f24, 0x23f3e-0x23f44).
- Seq_remarkEventRange (0x23654) and Seq_cmdHandler10 (0x23af7) store through the NULL record Seq_listGetAt leaves for an empty track list: the original faults, the port
  faults (SG_E_FAULT) the same way.
- Midi_Device::emitEvent's slot sweep calls virtual slot 0x28 on each member of an object's `s[0x1440 + 4j]` array without a NULL test; the port keeps that.
- Midi_Device::loadFile / loadFromMemory read the track chunk size with no bound and allocate it with operator new; a failed allocation leaves a NULL track
  whose stores fault (the node append stores through a NULL node: 0x1db16-0x1db5c).
- The C3 hook comments cite thunk addresses for some callees and the body for others; both resolve to the same port function (U-1445).

## For S4.2b (core consolidation; lead's request after S4.8's acceptance)

- Stack-local handling is behind one helper, `fcell(ctx, n)` in the head of audio_seq.cpp (5_parts/head.cpp). Every use is `fcell(ctx, N)` for the address of a
  local plus ordinary `ld` / `st` on it, so moving to SndLocals / the harness's entry esp frame is a mechanical replacement of that helper. Cell numbers are
  unique per function (0..24); with a real per-call frame they can all become locals of the calling function.
- Runner features this step needs from sound_replay.py (now in log/roadmap/S4/5_run.py, a copy of S4.6's 6_run.py): its own mirror DLL / golden file; the x87 control word
  of each vector stored in the bundle (`fpcw`, read from Unicorn's FPCW and normalised 0x023f -> 0x027f) and applied by the replay (`sg_set_fpcw`, Win32);
  the X87_WIN32 status (x64 mismatch at a non-default word is judged on Win32); the fallback-owner count by step (OWN_STEPS gate); mode-2 x87 control (`x87ctl`);
  Win32 library loader over the mirror's runner (`load_w32_6`). Not needed here: derived keys, synthetic keys, the sNaN quirk filter (QUIRK_KEYS empty).
