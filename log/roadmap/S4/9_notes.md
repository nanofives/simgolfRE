## 2. Method (decision G1)

The original runs in Unicorn over the user's sound.dll on a fixture VM, the port runs on the same memory in three layouts A / B / C; the return and every
region byte must match (tiers EXACT / EQUAL_PI / EMU_ONLY). Rows with no registry key (the emu-only rows) got hand-made keys:
writeWaveChunk@wwc (8 rows), writeWaveChunkB@wcb (8), writeWaveFileB@{noeng, empty, nullobj, k6, k4, k1, k1b, mix}, Wave_Device::open (12 scenarios),
Wave_Device::start (15), Wave_Device::dispatchCommand@gen_{post,thread} (27 devices), fillDecodeRing@x1 / x2, onWaveInCallbackMessage@{4},
setOutputMasterVolume@{dev, null}. Callees other steps own run as a development fallback (a host call to the original code), counted by owner step;
the gate fails only for fallbacks into accepted steps or S4.9.

## 4. Findings (defects of the original the port keeps, U-1481, U-1482, U-1489)

- writeWaveChunk (0x7e69-0x7e8d, 0x7f35-0x7f59) and writeWaveChunkB's four clamp loops end with `dec ecx; jne`: a zero count runs 2^32 times.
- Wave_Device::readFmtChunk reads a file-supplied size into the 0x18-byte area at the CtrlObject's +0x10; the +0x28 slot is the SEH record link.
- Wave_Device::deviceName stores a BYTE through its second argument (NULL device).
- Emulator quirk (U-1451): Unicorn keeps a signaling NaN signaling through fld / fst where the CPU quiets it; a difference of exactly the quiet bit
  is forgiven for QUIRK_KEYS = closeMmioSound (quirk9.py), recorded in the golden as `quirk`.
- SEH / C++ EH states are not modelled (U-1483): the ported bodies run the straight-line path; the original's unwinding arms are the uncovered spans above.

## 6. For S4.2b: names and frames

- NAMING RULE from the lead (log/roadmap/merges/S4-3.md): sound.dll functions are registered as `snd.<hooks.csv name>`. This step was already
  built, run and goldened under the bare names when the rule arrived, so it was NOT migrated here. Every place that carries a registered name goes
  through one mapping, so the migration is mechanical:
  1. `port/test/sound_replay.py` `port_name(key)` (shared file, not edited): return `"snd." + rows[0]["name"]`. Everything in 9_replay.py, quirk9.py
     and test_audio_wave.py maps keys through `R.port_name`, so they follow.
  2. The FuncDef names in audio_wave.cpp: generated by 9_assemble.py from the `// FuncDef: {"<name>", ...}` comments of the converter output and the
     hand blocks; add the prefix in the one place that builds `table` (the `m.group(1)` line) and re-run `9_assemble.py`.
  3. The negctl calls: `lib.negctl(fn, mode)` takes the registered name (via port_name in sound_replay.py); `SG_SINK_NEGCTL=<fn>:<mode>` takes the
     registered name as well (`closeMmioHandle` -> `snd.closeMmioHandle`).
  4. `emuonly9.py`: QUIRK_KEYS is compared with `R.port_name(key)`: change `("closeMmioSound",)` to `("snd.closeMmioSound",)`.
  5. Regenerate the goldens with `oracle --update` (digests do not depend on the name; the `fallback_owners` and `quirk` keys do not either) and re-run
     negctl, replay x64 / Win32, sinklog, pytest.
  Calls between modules by name (`audio_dev.esp`, `audio_dev.fpcw`, `audio_core.setup`) are not sound.dll functions and stay.
- `WaveFrame` (head of audio_wave.cpp) is the only stack-local helper of this module: replacing it with the consolidated core's API is one class.
  All 14 functions that pass a local's address (U-1480) go through it.
