## 1. What the original does (cited; the port's file cites functions by name)

- The sprite queue: buildSceneSprites and the frame's P1..P3 fill it (enqueueSprite) or draw at once (addSprite ->
  drawQueuedSprite); P4's renderSpriteQueue (golf_clean.exe 0x00463100, only caller mainLoop) draws every entry in list order.
  drawQueuedSprite (0x00462be0, c3ei.cpp): d = 0x10 (0xd above a 1000-pixel screen, 0xa from 0x4b0, 0x10 for a golfer entry);
  shade 0 or flags -1: Surface_blit2 (0x004740f0) with g_halfBrightLut at the scale in force; otherwise Display::setScale
  (s, s, d) with s = shade * g_zoomScale (shade < 0: -(shade * zoom), d doubled), then by flags: 0x100 composeGolferSprite
  (0x00462020) + Sprite_draw (0x004741b0) with g_images[0]; 0x800 / 0x400 Sprite_drawScaled (0x00474260) with colour 0x7c00 /
  0x7fff and g_images[flags & 0xff]; 0x200 Surface_drawSprite (0x00474440) alpha 0.6 (0x3f19999a) with g_images[flags & 0x1ff];
  else Sprite_draw with g_images[flags]; finally the scale restored to (z, z, 4), z = g_zoomScale when g_spriteFlag8371f8
  (0x008371f8) != 0, else g_sprite58b384 (0x0058b384). P6 sets (1, 1, 1) through the display slot +0x9c (ML+0x96ff, ML+0xa1a2).
- The exe wrappers reach the jgld Sprite vtable 0x1011d380 (log/roadmap/S3/5_tools/vt.py): Surface_blit2 -> slot +0x6c
  Sprite::drawG (0x100165a0) -> draw16_10028630; Sprite_draw -> +0x78 Sprite::blt16a (0x10019830) -> draw16_100298b0;
  Sprite_drawScaled -> +0x4c Sprite::blt16c (0x100199d0) -> draw16_10024140; Surface_drawSprite -> +0x94 Sprite::drawAlpha
  (0x10018920); Image_draw -> +0x44 Sprite::drawB -> drawB8to16 thunk 0x10001a50 -> draw16_1001bc40. Their trim offsets
  m_20 * nx / den + x use the display scale in force (Sprite_draw / Surface_blit2) or the one they set (drawScaled2 /
  Sprite_drawScaled); Surface_drawSprite adds m_20 unscaled.
- draw16_100298b0 (plane blit): 0xff transparent, < 0xf8 the palette's 16-bit word, 0xf8 + k the word (k << 15) | destination of
  the 4th argument's table (the binary's operand is 0x10128574, which re/match/jgld_blit16b.cpp names g_10128548; CLAUDE.md
  notes the masking). drawQueuedSprite passes g_color16Lut: build16BitColorTable's five 0x8000-word blocks (c3ad.cpp: steps
  0x400..0x700, block 5 brightenComponent). Payloads 0xfd / 0xfe read past the five blocks (U-1343).
- The blitter skeleton (all bodies): unscaled when |nx| == |den| and |ny| == |den| (IntersectRect with the clip rect);
  otherwise fx = (float)|nx| / den, rectangle (x + (int)fx, y + (int)fy, (int)(w fx), (int)(h fy)), steps (den << 16) / |n|,
  source column floor((offX step + i step) / 2^16), row floor((offY step + j step) / 2^16): the row carry reads the skip table
  through 0x10122e20 (= 0x10128550) with index -1, and 0x10122e1c holds 0x1012854c, the dword before it (read from jgld.dll).
- Sprite::blt16a / blt16c set the Sprite's +0x10 palette word from their key and never restore it (`saved` unused); drawG,
  drawB and drawAlpha restore it. This settles U-1332: a sheet cell draws with its queue entry's g_images palette.
- drawAlpha on an RGB555 surface (format word 1) runs the second body of each pair; tolerance 0x1011d378 = 0.03125; 15 bodies
  by alpha window (gfx_scene.cpp alpha_body). Their 16-bit store keeps the shifted fields without a final >> 4
  (jgld_1.tsv's finding: only red's lowest bit survives).
- composeGolferSprite composes PALETTE g_images[0] from part palettes g_images[idx + 1] (and slots 140 / 141), each layer
  getRGBRange(work, 0, n) then setRGB(work + 3 c1, c1, c2) (c3ck.cpp semantics); entries a layer's n does not cover come from
  the stack buffer (U-1342).
- loadWorldAssets' palette loads (c3fv.cpp kWaPal* / kWaSw* / kWaD1..D4 tables and the written-out Pal calls): the files'
  palettes into g_images slots (water 178, trees 40, flowers 49, tall trees 53, ...). The port's menu.cpp has no palette loads
  (drawing state); gfx_scene.cpp's `loadWorldAssets.palettes` runs them (tables generated by 5_tools/wa_tables.py).
- buildSceneSprites' Surface_drawSprite alpha: *tbyte * f_k_dbl_4ba818, kind 4 *tbyte * f_k_dbl_4ba478[1] + [0] (0.04, 0.2;
  c3fj.cpp); the port's tick_scene.inc passed 0.0f, and its drop slots carried the float by value (merge edit 7).

## 5. The sprite-pixel gate

- Method (log/roadmap/S3/5_sprite_gate.py, test_gfx_scene.py frame tests): framegate runs a scenario twice, mode 0 and the
  TEST-ONLY mode 7 (every scene write inverted). The pixels that differ are the ones whose final value came from a scene draw (the
  mask). Those pixels are compared with the reference back buffer (log/c3/alt/refs). A one-level difference counts apart: it is the
  terrain rasteriser's G2 allowance inherited by blends (U-1347).
