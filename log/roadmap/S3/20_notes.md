## 1. What changed

- `gl::wgl_self_check(ctx, variant, perturb)` (gl_wgl.h / .cpp). It runs the port's own GL setup from the user's install through
  GameFiles: the Terrain constructor without a context, initSystem(800, 600, flip) and initTerrain, the same functions
  sg_gl_setup_to_raster uses. The setup goes into a `SetupPair(NameSink, WglSink)`, so texture names are chosen by the original
  driver's rule and mapped in the sink, as LiveTerrain's live path does. The check then draws the reference pass into a cleared DIB
  and compares SHA-256 of a 32 x 32 rectangle with the pinned hash.
  - `gl::raster_self_check` draws the same reference through GlRaster (test-only).
  - `gl::sha256_hex` is FIPS 180-4, checked against hashlib in the tests.
  - Harness entries: glWgl.selfCheck(variant, perturb) and glWgl.rasterCheck. They write `$wgl/selfcheck.txt` / `rastercheck.txt`
    and the rectangle.
- The reference: port/src/sim/gl_wgl_ref.inc, generated by `20_make_ref.py` (`--check` verifies the committed file).
  - Source: the original's recorded pass port/corpus/gl/c7/snaps/z2_r1. That is a zoom-0 render pass (Terrain +0x1c = 0; the
    projection the recorded state left equals sandbox's), the first pass after a windowPaint, so dib_pre is 0 everywhere.
  - The cut: every GL_TRIANGLES whose window bounding box (the pass's modelview, the recorded projection, the 800 x 600 viewport)
    comes within 3 px of the rectangle (616, 528, 32, 32), in the recorded order, with its binds. The current normal is restored
    before immediate-mode vertices; none was needed here.
  - Result: 19 of the pass's 2,646 triangles, 30 array vertices, 343 program words, 4,992 bytes.
  - Pinned: SHA-256 of the ORIGINAL's dib_post over the rectangle, f270e5be...b7520d291. All 1,024 pixels were written by the pass.
  - No texture, lighting value or file byte is in it; the geometry is recorded run-time values (U-1817).
- `LiveTerrain::choose_renderer(mode)` (terrain_live.h / .cpp), called before the first Terrain call:
  - raster = GlRaster;
  - wgl = the host GL without the check (S3.15's opt-in);
  - auto = the host GL when the sink exists and the self-check passes, else GlRaster.
  - The choice keeps `RendererChoice {mode, backend, reason, checked, check}`.
  - The sink variant follows the negative controls 8 / 9 / 11 / 12, and 13 / 14 perturb the check itself.
  - SG_GL_BACKEND now takes raster / wgl / auto.
  - Harness entry terrainLive.renderer(0 raster | 1 wgl | 2 auto) writes `$wgl/renderer.txt`.
  - The library default stays GlRaster (an unset SG_GL_BACKEND), so segments, boot, test_terrain_live and every library test that
    attaches a LiveTerrain are unchanged.
- The app (port/app/main.cpp; S7 file, a small change):
  - New option `--gl auto|wgl|raster`, default auto.
  - TerrainGuard::attach(o, ctx, rec) chooses before the first Terrain call.
  - It prints `simgolf_port: terrain renderer <backend> (--gl <mode>): <reason> [self-check <n> ms]` to stderr.
  - It writes `terrain_renderer.json` into the record directory, in all three run modes.
- framegate.py: `--gl auto|wgl|raster` (default auto) and run_scenario(gl=...). New columns `renderer` and `renderer_reason`;
  `--host-gl` is kept.
- gfx_terrain.cpp:
  - documents controls 13 / 14 and the G13 default;
  - SG_TERRAIN_PASS_LOG now also logs host-GL passes (counts -1, workers 0);
  - LiveTerrainView::pixels_drawn stays 0 on the host-GL path (waits.tsv terrain_pixels is 0 with it).
- Tests:
  - test_gl_wgl_selfcheck.py (new, 20 tests).
  - test_gl_wgl.py: the old default test now asks for `gl="raster"` (same 125 px); a new test checks that the default equals the
    `--host-gl` rows.
  - test_app_ingame.py `replay` and test_app_live.py `_live_terrain` (the lead approved this): the library replay draws with the renderer the session's app
    recorded (terrain_renderer.json; a headless session has none, so GlRaster). The expectation "app present == replay snapshot"

## 8. Measurement: the band option for the host GL (lead's request, 2026-10-30; measurement only, not in 20_edits.py)

Code: `20_band/` (glband.c + glband_exec.inc + build.bat: a standalone x64 replay of the original's recorded c7 passes, glreplay.c's method;
cut.py: per-band cuts of a pass; fg_band.py: framegate rows; thread_rip.py: where a spinning thread is; band.patch: the port-side
`WglBands` sink, renderer mode `wglband`, SG_GL_BANDS / SG_GL_DEFAULT, applied to the mirror for the runs and then removed again, so
port/build/S3_20 equals the 20_edits.py tree and its x64 build is that tree's, 20_build_x64c.log).

Method. N contexts on N threads, each with its own full 800 x 600 555 DIB, glScissor limiting it to rows [H*k/N, H*(k+1)/N) (memory row =
window y for biHeight > 0); the bands' rows composed. Two variants: (a) every band replays the whole pass; (b) a band replays the state
calls and only the glBegin .. glEnd blocks whose window bounding box comes within 3 rows of its band, with the current normal and texture
coordinate each block started with (the 20_make_ref.py cut). In the port (band.patch) the pass is recorded on the calling thread and
replayed by persistent workers; the setup and every call outside a pass go to all workers; a band no block reaches is skipped.

Pixels (every check against the single context, which itself equals the original's dib_post):
- c7, all 34 recorded passes: (a) N = 1, 2, 4: 0 px differ (20_band/eq_all.log); (b) N = 2, 3, 4, 6: 0 px differ (eq_cut_all.log, 33
  passes in the full run plus z2_r3 in 3 single runs). The first cutter differed on 13 passes: it dropped the passes' glEnable /
  glDisable / glBlendFunc toggles and ignored glVertex3f triangles; fixed in cut.py, then 0.
- framegate (band.patch, variant b): sandbox_basic 10, cov_k3_camera2 25, cov_a_keys 23 checkpoint images at N = 2, 3, 4, 6 equal the
  single-context host GL's in every pixel, rows equal (20_band/fg_band.log, fg_band2.log); the startup self-check passes through the bands.
- app: test_app_ingame's session with `--gl wglband` (N = 4 and 6): every present equals the replay drawn with the single-context host GL
  (test_ingame_presents_equal_the_port_back_buffer passed).

Times (LIVING-PC, Ryzen 5 3600; other sessions kept the CPU at 47..82 % busy, so these are under load):

budget with margin (max 46..50 ms against 87), but a hang inside opengl32 was seen once in the port's band path and once in the
standalone tool, cause not established; shipping it as the default needs that settled (e.g. a watchdog that falls back to the single
context or GlRaster, and a longer stress run).
