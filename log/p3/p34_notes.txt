2. Method and x87
- Bodies transcribed from the C3 hooks (shim/src/re/c3ea.cpp trialShot / simulateBallFlight / simulateShot, c3a.cpp
  shotPower, c3dr.cpp wobble, c3dy.cpp scanShotArea, c3fr.cpp narrateShot), each of which cites its instructions, and the
  analysis notes; data addresses mapped to GameState members (golfer record offsets per golfer_record.md: hole n's target
  tile = g_holes + 0x18 + n * 0x208, type attribute byte k = g_tileTypeAttrs + 0x20 + 0x30 t + k, trialShot's record
  copy = golfer 155, narrateShot's snapshots = golfers 152 / 153). Strings by (pool member, offset) per CORE.md 6.
- The cycle's own x87 code is `fild; fsqrt; __ftol` (prepareShot 0x00424289, 0x00424519; chooseShotTarget 0x0042317b,
  0x004233e1). sqrt_ftol runs it as inline x87 on Win32 (chop set for the fistp like __ftol) and as SSE2 on x64. For an
  int32 argument the truncated root does not depend on the rounding control at 53- or 64-bit precision: for n^2 - 1 <
  2^31, sqrt(n^2 - 1) is below n by about 1 / (2n), far more than one ulp of n, and an exact root is exact in every mode.
  At 24-bit precision (precision control 00) that gap is below one ulp for n > 2896, so a root of n^2 - 1 can round up
  to n there; no vector has such a distance (all GREEN at 0x007f too) and the game never sets that word.
  Measured: trialShot, prepareShot and chooseShotTarget vectors give the same verdicts at 0x027f, 0x037f, 0x0f7f,
  0x0b7f and 0x007f on the Win32 backend (test_square_root_is_control_word_invariant runs the first four); a body that converts under the
  current rounding instead of chop (prepareShot negctl 3) reads RED on 54 vectors on both backends. Random::range and
  distance are util's (C++ doubles; exact at 0x027f, the vectors' word).
- Uninitialised stack slots start at 0 (U-0880); prepareShot's counts[] / dirs[] / 2500-byte array are one frame array
  indexed like the original's, a negative tile type throws FrameOverrun (U-0882).
- Build note: the shared build was broken for long stretches by other children's work in progress; 3.4 tested in a
  private copy of port/ (scratchpad) with only compiling modules. MSBuild does not rebuild registry.cpp when
  src/sim/modules.inc changes (registry.obj stayed stale in the copy: newly listed modules were missing from the
  registry); touch registry.cpp after editing modules.inc.
- Until 3.1a registered its five functions, a scratch-only transcription of them (never committed) let the cycle be

3. Defects (re/analysis/data/model_defects.md, switches in shots.cpp, default 1 = the original)
- shotPower.cacheIgnoresPutt (#18): OFF = putt calls bypass the cache; OFF changes exactly the 32 shotPower vectors with
  putt != 0 (test_defect_shot_power_putt).
- chooseShotTarget.strictFlagSticky (#37, new): [F+0xb4] is never initialised or cleared, so after one qualifying landing
  every later strict scan of the search runs with 1. No vector sees it (test_defects_the_vectors_cannot_see).
- prepareShot.hazardCellTransposed (#38, new): the hazard probe passes y * 50 + x to the thoughts. OFF changes 2
  real-shot vectors (simulateShot_mode+unstub), all with x == -1 (test_defect_hazard_cell_transposed); before 3.1a's real
  terrain callees were registered no vector reached it.
- narrateShot.maskNotRestored (#39, new): two missed-shot exits (0x00408c24 -> 0x004095d3, 0x00408c6f) return before the
  mask restore 0x00408fae. Shown on a constructed state (test_defect_narrate_mask_not_restored).
- trialShot's edge reads outside the grid (#5) and the never-run debug overlay (#31) are reproduced by Ptr / kept as is.
