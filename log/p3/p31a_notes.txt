4. The Terrain.dll boundary (U-0607)
- Every exe function that calls Terrain.dll was checked for what it writes outside Terrain.dll: engine-class
  g_terrain820f28 / g_terrain820f2a / g_terrain820f30, pointer-class gTileBuffer / g_terrainListCursor, and in
  updateTerrainRender the sim-class camera memory g_terrainInitPending / g_terrainLastCamX / Y / g_terrainLastZoom (from its
  arguments) plus g_tileWallMask[0] bit 1 (set after rebuildTileData, cleared by rebuildHeightfield's tail). No sim-class
  write depends on a value Terrain.dll returns: Terrain.dll's state feeds rendering only.
- So the port models Terrain.dll as an interface, portsim::TerrainApi (terrain_api.h): the 20 imported methods the sim
  functions call plus the engine services the same functions reach (input pump, window paint, the two blits,
  renderTerrainStrip, the display surface DC, GetVersionExA's major version, operator new for the render list's nodes).
  Every method returns the original's eax. The Terrain object stays in the 32-bit address space (gTerrain holds its
  address); the exe-side code reads its fields like the exe (width +0x14, height +0x18, tiles +0x3a4 of 0x248 bytes,
  tile type +0x24, corner heights +4 + 8k, walls +0x234 + side) and passes Tile pointers as addresses. A renderer
  backend (phase 4) implements TerrainApi; set_terrain_api(ctx, api) attaches it (side table in terrain_dll.cpp, no
  shared-header change); without one the functions throw MissingResource.
- Tests: terrain_fake.cpp is a recording fake behind TerrainApi (calls logged as 8-dword records in a mapped block, every
  eax a pure function of the arguments, corner heights move by one per elevate / lower, setType / layPath / setWall keep
  fields). test_terrain.py's PyFakeTerrain mirrors it and serves the ORIGINAL code in Unicorn at the Terrain.dll import
  traps and at the engine functions' entries (pumpInput483bd0, Window::paint, Surface_blitThunk, renderTerrainStrip,
  operator new / delete, playSound, the surface vtable slot +0x28, GetVersionExA). A scenario compares eax, the call log,
  the GameState, the Terrain object and the heap block.

5. Design decisions (each also an uncertainty row)
- pathStep's debug overlay (g_flags bit 0x1000): its g_textBuffer / g_textBuf writes are kept, the drawing and the
  pumpAndRedraw(0) wait for a click are dropped (U-0802; the same rule as 3.4's U-0881).
- showPopup (a ui modal, phase 3.7) answers demolishObject's confirmation and buildTournamentPrep's par changes: it is
  called through the registry and is a MissingResource while nothing registers it (U-0803).
- customizeCharacter: showCharacterIntro (ui) and playSound (audio) are called only when registered (U-0804).
- initTerrain's GetVersionExA major version comes from TerrainApi::os_major_version (U-0805).
- rebuildTileData pushes render-list nodes; the node memory comes from TerrainApi::operator_new, the erase in
  updateTerrainRender only unlinks (no heap model, U-0823).
- rebuildHeightfield's relax / raise pass loops until a sweep changes nothing; the port throws NoReturn when a level grid
  repeats with changes (the original would spin forever there).
- buildGolferBioText's arrival pick loop throws NoReturn when no type 0..75 can satisfy the pick (residue, membership
  byte, class): the original spins forever.
- Callees owned by other children are called through the registry by their hooks.csv names (landmarkName, clearBuffers,
  initRecords, loadThemeFile, freeRecordAtPos: 3.1b; resetGolfer, placeHabitat, spawnWalker: 3.3; updateMembership,
  rateLot: 3.2; pointsPopup: 3.3's bridge when registered, else a local copy of its body, as golfers_glue.inc does).

6. generateRandomCourse (0x00470a60, terrain_gen.cpp, written by a local helper agent from the c3ed hook + disassembly)
- Sections A..M; the course record fields read are location_id (c0), acres, relief (c2), setting, course_type, year_bought;
  hole 19's tee slots hold the clubhouse position; spawnWalker (3.3) through the registry, the rest direct calls.
- Oracle (test_terrain_gen.py, own Unicorn runner, 500 M instruction budget): 97 random cases (c0 0..16, settings 0..2,
  course types 0..3 plus the 4 / 5 bodies, difficulty 0..3, flag 0x01000000, rng / year / relief): 96 byte-equal, 1 both
  spin (#79: c0 == 1 on an island desert course has no type-0x11 tile, so its search never ends; the port throws NoReturn).
  Dense random 0x8080 / 0x400 flags or g_objectTypeLevel up to 119 make the original spin too (every clubhouse spot fails /
  a kind-9 building covers the map): the scenarios use sparse flags and levels 0..3.
- Unbounded random-cell searches (clubhouse, c0 4 / 1 / 5-group / 0-10, sections I and L): after 65,536 consecutive misses the
  port checks every cell the RNG can produce and throws NoReturn only when none qualifies (state does not change while the loop
  misses, so that is a proof); otherwise it keeps looping.
- The uninitialised base type (course type 4 / > 4): MissingResource at the first read (U-0801, model_defects#52).
- Default tests on a fixed image (settings 0..2): eax = final g_flags, course index / type / year writes, relief, clubhouse
  record and camera, the posted walker, every border-sweep cell, g_tileTypeSaved, determinism, NoReturn on an all-0x8000 image.
- Controls: camera y = column - 3, the setting != 2 border sweep skipping the far column, corner levels filled 50 x 50: RED in
  the default tests and in the oracle.
