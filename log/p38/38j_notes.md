## 2. What was ported

1. **The menu and session bodies** (port/src/sim/tick_menu.inc, generated by `log/p38/38j/conv_menu.py`): log/p3/p37a_conv.py over
   shim/src/re/c3fy.cpp's part MV (Menu, MV_blitFull: ML+0x11875..ML+0x12050), part SV's Session (ML+0x43c..ML+0x664) and
   Setup's stores of the menu's frame slots (MenuSeedSlots), then asserted edits: SV's unused clock helper removed, comments
   corrected (U-1053), four negative-control switches. Every callee is called by hooks.csv name: registered ports,
   documented drops (Surface_blit3, Image_draw, drawCenteredText, setDrawTarget, loadImage, Image_ctor / dtor,
   Window::refreshFull, waitTicks, startSoundSlot, playSound), the tick locals pumpInput483bd0 / pumpMessages, or
   MissingResource (the theme and quit paths: U-1050). `menu_session` is MainLoopBody's loop: seed, Menu, Session; Session's
   sMenu goes back to the menu, sQuit is FrameExit::Quit, sFrame runs rebuildTileCoverage (ML+0x664) and returns
   FrameExit::Frame.
   - Setup's slots: the menu's hotspot table F+0xf4.. and item table F+0x150.. are written by Setup only
     (`log/p38/38j/slotscan.py` lists every write of F+0xf4..0x10b, F+0x150..0x16b, F+0x1f4..0x207 in mainLoop: Setup's
     0x0040f67d..0x0040f7b6 and nothing else); Setup runs once at boot, so writing its constants on every menu entry gives the
     slots the values they have at any time after boot. The port's frame block starts zeroed.
   - The frame's exit to the menu (kMenu from H1 ML+0xf106 or H2's quit save) now continues in the same frame step, so the
     menu and the screens it opens consume the rest of the exiting frame's trace records (the next FRAME record is the
     first frame head after the session).

## 3. The menu's selections (U-1053, a doc correction)

Hotspots 0..5 (labels Continue Saved Game, Start New Game, Select A Theme, Play a Championship, Sandbox Mode, the quit spot)
map through the table 0x00421b04 to the selections 1, 0, 4, 2, 3, -2. Selection 2 (championship) runs the difficulty screen
and sets g_courseType 0xff and g_flags bit 26; Session then calls startNewCourse. Selection 3 (sandbox) sets cash 100000, g_flags
bit 24, g_difficulty 1, and Session's new-course path unlocks every building and amenity. mainLoop_structure.md had 2 and 3 the
other way round (merge item 7). Paths of the four gate segments: cov_b_career_types = Start New Game -> difficulty ->
courseActionMenu -> loadWorldAssets / generateRandomCourse / rebuildHeightfield; cov_k1_animals = Sandbox Mode ->
courseActionMenu -> the same; cov_b_shots = Play a Championship -> difficulty -> startNewCourse (course list, pro list,
loadGolfPro) -> loadWorldAssets.

## 5. The H2 retile exit

H2 with no tool (ML+0x10919, `f_w_4c2848 == -1`) returns kRetile: the original goes to ML+0x664 (rebuildTileCoverage) and then
its frame head ML+0x669, where the frame record is taken. tick_run_frames used to hash the record first and rebuild at the
start of the next step. Frame::run now rebuilds in the exiting step (merge item 2c). Every one of the other 196 segments has
the same digest (every frame record) with this change, so where they take that exit the rebuild changes no sim object.

## 8. Files and how to rebuild

- Generators: `log/p38/38j/conv_menu.py` (tick_menu.inc), `log/p38/38j/gen_flics.py` (menu_flics.inc); both take `--check`.
- tick patches: `log/p38/38j/tick_patch.py --diff` writes tick_cpp.patch / tick_h.patch from the working tree; `--apply [root]`.
- Private build: `~/bin/py -3.12 log/p38/38j/mirror.py --mine [--arch x64 Win32] [--tag t]` -> port/build/38j_run/<arch>_<t>/.
- Diagnostics: log/p38/38j/gapdump.py, gapbatches.py (the records and dispatch batches of a frame), slotscan.py,
  after_wait_census.py, oracle_cover.py, disas.py.
- Tests: `SG_PORTSIM_DLL=<dll> ~/bin/py -3.12 -m pytest port/test/test_menu.py` (add SG_EMU_ORACLE=1 for the oracle,
  SG_EMU_ORACLE=update to re-pin the digests).
