## Purpose
Gives a tile a variation, a rotation and a terrain type, in that order, and is the only exported way the exe changes a tile's type (`syncTiles` 0x00449470, `rebuildTerrainGrid` 0x00449540 and `applyTileVariation` 0x00449f00 call it through the import slot 0x4ba19c). The second argument indexes a table of 0x18-byte records inside the Terrain object at +0x40, whose first dword is how many art variations that type has (imul eax, eax, 0x18 at 0x10003310, cmp dword [ecx+eax+0x40], 0 at 0x10003316); nothing bounds the index against the table. The test is signed (jle 0x1000331b): a count of one or more makes the body draw a variation with the module's own CRT rand 0x10018ce0 (call 0x1000331d) and keep the remainder of the signed division by the count (cdq 0x1000332b, idiv 0x1000332c), while a count of zero or less passes the literal 0 (push 0 at 0x1000333b); either way the value goes to Tile::setVariation through the thunk 0x100010b9 (0x10003334 / 0x10003340), which stores it at Tile+0x240. Then the third argument goes to Tile::setRotation through the thunk 0x10001050 (0x1000334c), which stores it whole at Tile+0x28 - the field Terrain::getVariation reads back as a signed byte - and the second argument goes to Tile::setTypeId through the thunk 0x10001235 (0x10003358), which is what re-blends the neighbourhood and runs the type's enter and leave walks. rand reads and rewrites the per-thread seed at _getptd() + 0x14 (0x10018cef, 0x10018d01), so that seed is both an input and an output of this body and is part of the A/B's state.
