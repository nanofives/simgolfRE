## Purpose
Move the keyboard focus of a view's child list onto one item. Nothing happens for a null item (0x0047ae87 / 0x0047ae8c) or a child count at this+0x140 that is exactly zero (0x0047ae92 / 0x0047ae9a). The item that currently holds the focus is the one the node at this+0x13c points to in its +4 (0x0047aeaa / 0x0047aeb0), or none at all when the list head at this+0x138 is null (0x0047aea0 / 0x0047aea8 / 0x0047aeb5); when it is already the requested item the function returns (0x0047aeb7 / 0x0047aeb9). Otherwise that previous item is parked in the global 0x0083ab98 (0x0047aebf) and a null list head ends the function there (0x0047aec5 / 0x0047aecd). The search rewinds the cursor - the index at this+0x144 is cleared and this+0x13c set back to the head (0x0047aedd / 0x0047aee7) - and a child count that is not POSITIVE ends the function (0x0047aedb / 0x0047aeed), which is how a negative count passes the first test and fails here. The walk compares each node's +4 against the item (0x0047aeef / 0x0047aef5 / 0x0047aef8) and on a miss increments this+0x144, follows the node's +0xc link into this+0x13c and stops after the child count iterations (0x0047aefa / 0x0047af02 / 0x0047af08 / 0x0047af0b / 0x0047af0d / 0x0047af13), leaving the cursor past the end. On a hit the previous item is told it lost the focus, but only when there was one and the child count is MORE than 1 (0x0047af1c / 0x0047af20, a signed compare), through its own vtable slot +0xf0 with argument 0 (0x0047af29 / 0x0047af2d); the list head and the node the cursor now points at are then read again (0x0047af33 / 0x0047af3b / 0x0047af3d / 0x0047af43) and that node's item is told it gained the focus with argument 1 (0x0047af46 / 0x0047af4a / 0x0047af4e). The function is slot 75 (+0x12c) of the View vtable family: staticInit_404360 0x00404360 installs it in the table at 0x004ba2fc (and View::ctor 0x00479c40, Button::ctor 0x00488500 and ten more install the same slot in their own tables), and no `call` instruction in the image targets the body.
