## Purpose
Reports bit 4 of the flag byte at +0x38 of the track at a given index of the sequencer's this+0x60 list. The track count comes from the sequencer's own vtable slot +0xb4, called with the sequencer in ecx and nothing pushed (`mov eax, [esi]` / `call dword [eax+0xb4]` at 0x10023f14, 0x10023f16). The index is rejected when it is ABOVE that count (`cmp ecx, eax` / `jbe 0x10023f2b` at 0x10023f20, 0x10023f22, UNSIGNED): `jbe` ACCEPTS index == count, unlike the `jae` reject of Seq_applyTrackFlag 0x10023e10 one page away. On the rejected path only `xor al, al` runs (0x10023f24), so the dword the body returns is the COUNT with its low byte zeroed, not 0 (measured: the count 0x105 returns 0x100). Otherwise Seq_listGetAt (VA 0x1001d780, through the incremental-link thunk at 0x10023f34) is called on this+0x60 (`lea ecx, [esi+0x60]` at 0x10023f31) with the index as the step count and a local slot as the out pointer (`lea ecx, [esp+8]` at 0x10023f2c), the record it wrote is read back (0x10023f39) and bit 4 of its byte at +0x38 is extracted (`mov al, [edx+0x38]` / `shr al, 4` / `and al, 1` at 0x10023f3e-0x10023f44); by then eax holds Seq_listGetAt's own return code, so on this path the dword is that code with its low byte replaced by the bit. Seq_listGetAt writes 0 through the out pointer for an index past the end of the list and the body then dereferences 0x38, so an accepted index with no node faults in the original.
