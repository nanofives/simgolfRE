## Purpose
__ArrayUnwind is `__stdcall(end, size, count, dtor)` with `ret 0x10` (0x004a57ee), the destructor sweep of the eh vector constructor iterator: its finally funclet 0x004a563c calls it at 0x004a564e with (the element pointer reached, size, the number of elements constructed, dtor), and the funclet 0x004a577b calls it at 0x004a578d. Its prologue builds an SEH frame with scope table 0x004bc458 = {-1, filter 0x004a57cf, handler 0x004a57d9} and handler function 0x004a8f7c (0x004a5796..0x004a57a9) and sets try level 0 (0x004a57b8). The loop decrements the count (`dec [ebp+0x10]` 0x004a57bc) and leaves when it is negative (signed `js` 0x004a57bf); otherwise it steps the pointer back by size (`sub ecx, [ebp+0xc]`, 0x004a57c4 / 0x004a57c7), calls dtor as `__thiscall` with ecx = the pointer (0x004a57c1 / 0x004a57ca) and repeats (0x004a57cd): the last-built element is destroyed first, a count of 0 or below calls nothing. The filter (0x004a57cf..0x004a57d8) passes the EXCEPTION_POINTERS from [ebp-0x14] to 0x004a8975, which returns 0 (continue the search) unless the exception code is 0xe06d7363 (`cmp [eax], 0xe06d7363` 0x004a897b), for which it jumps to 0x004a8eba, which calls the terminate handler and does not return; so an exception a destructor raises with any other code leaves the sweep with the remaining elements untouched, and the handler 0x004a57d9 (which would restore esp and fall into the exit 0x004a57dc) is not reachable. The A/B ran 30 vectors on three fixtures with a recording destructor (it logs `this` and inverts the element's first dword; fixtures c3fz_unwind_none / _t0 / _t2): no destructor raises (15 vectors: sizes 0, 1, 4, 8, 12, 0x2c, 0x40, 0x10c and 0xfffffffc (the pointer walks up), counts 0, 1, 2, 5, 10, 40, -1, -3, -5, destructor NULL for the counts that call nothing); the first call raises (6 vectors: counts 1, 3, 2, 40 raise, 0 and -2 call nothing) and the third call raises (9 vectors: counts 3, 8, 5, 6, 4 raise; 2, 1, 2, 0 finish), the raise being caught by C3fzSehCall4 around the arm so the exception unwinds the arm's frames first: 30 vectors GREEN, 22 change state, 0 mismatches (the exception code is a compared state word). A count of 0x80000000 is not used: the decrement gives 0x7fffffff, which `js` does not take, so the original would run 2^31 iterations.
