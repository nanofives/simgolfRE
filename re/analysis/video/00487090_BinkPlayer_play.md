## Purpose
`BinkPlayer::play(this, path, offX, offY, soundParam)` opens one Bink movie, plays it to its end or to a key press, and is the only function that drives the player's frame loop. Without a target window at this+0xc it answers 7 and does nothing (`mov eax, [esi + 0xc]; test eax, eax; je` 0x00487093 / 0x00487096 / 0x00487098, `mov eax, 7` 0x0048709a). A non-zero fourth argument first hands binkw32 a sound device: `_BinkSetSoundSystem` [0x4ba248] is called with the ADDRESS stored in the `_BinkOpenDirectSound` import slot [0x4ba244] as its first argument and that argument as its second (pushes 0x004870ab / 0x004870b1, call 0x004870b2). It then sets the I/O block size to 0x9c4000 bytes (`_BinkSetIOSize` [0x4ba24c], call 0x004870bd), opens the path with the flag 0x1000000 (`_BinkOpen` [0x4ba250], call 0x004870cd) and keeps the handle at this+4 (0x004870d5); a NULL handle or a non-zero error word at handle+0x1c answers 1 (`je` 0x004870d8, `mov ecx, [eax + 0x1c]; test ecx, ecx; jne` 0x004870de-0x004870e3, `mov eax, 1` 0x0048716b). The drawing buffer is opened for the target window with the movie's width and height (`_BinkBufferOpen` [0x4ba254], call 0x004870f6) and kept at this+8; a NULL buffer answers 1 as well (`je` 0x00487101). The two offsets are given to `_BinkBufferSetOffset` [0x4ba258] (call 0x00487116) and stored at this+0x10 / this+0x14 (0x00487110 / 0x00487113). The pointer is then hidden (`ShowCursor(0)` [0x4ba200], call 0x0048712b) and the byte 0x0083ab9c is set to 1 (0x00487124). The loop at 0x00487133 asks `_BinkWait` [0x4ba25c] whether the next frame is due (call 0x00487137): while it answers non-zero the two input pumps pumpInput483c90 0x00483c90 and pumpInput483cf0 0x00483cf0 run and the loop repeats (calls 0x00487153 / 0x00487158); when it answers zero a cleared byte 0x0083ab9c ends the loop (`je` 0x00487144), otherwise BinkPlayer::frame 0x00487180 draws one frame and a false result ends it (`test al, al; je` 0x0048714d / 0x0048714f). The pointer is shown again (`ShowCursor(1)`, call 0x00487161) and the function answers 0 (`xor eax, eax` 0x00487165). It never closes the handle or the buffer: the caller does that through BinkPlayer::close 0x00487060.
