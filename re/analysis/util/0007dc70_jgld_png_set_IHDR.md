## Purpose
Fills a png_info with the nine values of a PNG header chunk and derives the three fields a row walker needs from them, which is what png_handle_IHDR 0x100796e0 calls once it has parsed the chunk. It does nothing at all unless both pointers are given (0x1007dc8c and 0x1007dc92, both landing on the `jmp` to the epilogue at 0x1007dc94). The seven header values are stored in the info in an order that is not the argument order: width at +0 and height at +4 (0x1007dc9f, 0x1007dca7), bit_depth at +0x18 and color_type at +0x19 (0x1007dcb0, 0x1007dcb9), and then the LAST argument but one at +0x1a (compression_type, 0x1007dcc2), the last at +0x1b (filter_type, 0x1007dccb) and the seventh at +0x1c (interlace_type, 0x1007dcd4). The channel count is rebuilt from the byte just stored rather than from the argument: 1 for colour type 3 (0x1007dcdf), 3 when bit 1 is set (0x1007dcf5), 1 otherwise, plus one for bit 2 (0x1007dd14, `add al,1` at 0x1007dd21); pixel_depth is channels * bit_depth truncated to a byte (0x1007dd39, 0x1007dd3f). The last step is the one png_read_transform_info 0x100714c0 does not have: before computing rowbytes the body divides 0x7fffffff by the bytes a pixel takes, ((pixel_depth + 7) >> 3) at 0x1007dd4a-0x1007dd5a, and compares that quotient with the WIDTH ARGUMENT as an unsigned value (`jbe` at 0x1007dd60); a wider image gets png_warning 0x10079040 with the module string 0x1011eb28 and rowbytes 0 (0x1007dd76), and only a width that fits gets rowbytes = (width * pixel_depth + 7) >> 3 (0x1007dd8c-0x1007dd98). The guard is of the row size alone, not of the whole image: height is stored and never read again. A bit_depth of 0 makes that divisor zero and the `div` at 0x1007dd5a faults, which is a defect of the original; no vector passes one. Reimplemented in `shim/src/re/c3bq.cpp`; path-1 A/B GREEN: png_set_IHDR (19 vectors, 18 distinct results, 17 changing state, `log/diff/0007dc70_jgld_png_set_IHDR.path1.csv`).
