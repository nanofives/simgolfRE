## Purpose
Runs the row libpng has just unfiltered through every transformation the caller asked for, in the one order the transformations are allowed to happen in, and is the only place that order is written down. Nineteen bits of the word at png_struct+0x70 are tested one after the other (0x1007182e for the first, 0x10071da3 for the last) and each one calls a single row routine with the header at png_struct+0x100 and the row at png_struct+0xec plus one (0x10071878 and its seventeen twins). The order is: PNG_EXPAND, PNG_STRIP_ALPHA, PNG_RGB_TO_GRAY, PNG_GRAY_TO_RGB (only when the image's background is not grey), PNG_BACKGROUND, PNG_GAMMA, PNG_16_TO_8, PNG_DITHER, PNG_INVERT_MONO, PNG_SHIFT, PNG_PACK, PNG_BGR, PNG_PACKSWAP, PNG_GRAY_TO_RGB again (the grey-background case), PNG_FILLER, PNG_INVERT_ALPHA, PNG_SWAP_ALPHA, PNG_SWAP_BYTES and PNG_USER_TRANSFORM. Four of the tests are not a plain bit test. PNG_EXPAND splits three ways on the row's own colour type and the transparency count: a palette row goes to png_do_expand_palette 0x10076ec0 with the palette at +0x114 and the tRNS array at +0x188 (0x10071886), and any other row to png_do_expand 0x10077300 with &trans_values (+0x18c) when num_trans is non-zero (0x100718c1) and with NULL when it is not (0x100718e4). PNG_GRAY_TO_RGB is tested twice against bit 0x20000 of the flags word at +0x6c, once before the background step (0x100719b4) and once after the packing steps (0x10071cac), so the conversion happens early for a colour background and late for a grey one. PNG_BACKGROUND only runs when the file actually has transparency - num_trans non-zero (0x100719fc) or the alpha bit of the png_struct's own color_type at +0x126 (0x10071a0b) - and PNG_GAMMA runs only when PNG_BACKGROUND did NOT, the same two conditions negated (0x10071aad-0x10071ad7), and the colour type is not a palette (0x10071ae4); when PNG_BACKGROUND does run it is png_do_background that applies the gamma. Three exits are errors rather than transformations: a NULL row_buf is formatted into a 50-byte stack buffer with sprintf 0x10082c80 and the module string "NULL row buffer for row %ld, pass %d" 0x1011de14 and handed to png_error 0x10078fe0 (0x100717eb-0x10071823); a non-grey pixel found by png_do_rgb_to_gray sets rgb_to_gray_status at +0x214 and then warns or fails, but only when the WHOLE transformations word equals PNG_RGB_TO_GRAY_WARN 0x400000 (0x10071967) or PNG_RGB_TO_GRAY_ERR 0x200000 (0x10071984), so a caller that asked for anything else at the same time gets neither; and a dither that leaves rowbytes at 0 is an error too (0x10071b95). Last, PNG_USER_TRANSFORM calls the caller's own function at +0x58 if it set one (0x10071db7) and then lets it override bit_depth from +0x64 and channels from +0x65 when those bytes are non-zero (0x10071def, 0x10071e0a), after which pixel_depth and rowbytes are recomputed from whatever the header now holds (0x10071e36, 0x10071e56) - the one place in the body that touches the header itself rather than leaving it to a callee. Reimplemented in `shim/src/re/c3bl.cpp`; path-1 A/B GREEN: png_do_read_transformations (35 vectors, 30 distinct results, 29 changing state, `log/diff/000717d0_jgld_png_do_read_transformations.path1.csv`).
