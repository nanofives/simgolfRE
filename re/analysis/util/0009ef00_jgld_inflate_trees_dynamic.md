## Purpose
inflate_trees_dynamic builds the literal/length tree and the distance tree of a dynamic deflate block from one array holding both sets of code lengths. The literal build is huft_build(c, nl, 257, cplens 0x101272bc, cplext 0x10127338, tl, bl, z) at 0x1009ef3b - the 257 at 0x1009ef2e is the count of "simple" values, so only codes 257 and above index the length and extra-bit lists. If it fails (0x1009ef46), Z_DATA_ERROR (0x1009ef4c) puts the module string 0x101209c0 in z->msg and Z_BUF_ERROR (0x1009ef5e) frees *tl at 0x1009ef6e, puts 0x101209a0 there and rewrites the result to Z_DATA_ERROR (0x1009ef80); either way it returns at 0x1009ef87 **without freeing anything else**, which is correct only because the literal tree is the one that failed. The distance build is huft_build(c + nl, nd, 0, cpdist 0x101273b4, cpdext 0x1012742c, td, bd, z) at 0x1009efb5, with the base pointer computed as c + nl*4 at 0x1009efb1 and a "simple" count of 0 (0x1009efa5) so that every distance code indexes cpdist and cpdext. Its two error arms (0x1009efc6, 0x1009efd8) use the SAME two module strings as the literal build's - zlib 1.0.2 spells both pairs "oversubscribed literal/length tree" and "incomplete literal/length tree", which is why one address each appears twice - and then fall into the shared tail at 0x1009f001, which frees *tl as well before returning (0x1009f013). Both builds succeeding returns Z_OK at 0x1009f018 with the caller owning both trees.
