## Purpose
Rewrites the png_info so that it describes the rows the caller is going to get after the read transformations, rather than the rows the file holds, which is what lets a caller write the transformed image back out as a valid PNG. It is the write-side twin of png_do_read_transformations 0x100717d0: the same nineteen-bit word at png_struct+0x70 is tested here (0x100714db and six further loads), but each bit changes a header field instead of calling a row routine. PNG_EXPAND 0x1000 (0x100714de) splits on the info's own colour type: a palette (0x100714f0) becomes colour type 6 when the png_struct has transparency and 2 when it has none (0x10071503, stores at 0x10071508 and 0x10071511), always at depth 8 (0x10071518), and any other colour type only gains the alpha bit when there is transparency (`or cl,4` at 0x1007153d) and is lifted to depth 8 only if it was below (`jge` at 0x10071551); both arms clear num_trans (0x1007151f, 0x1007155d). PNG_BACKGROUND 0x80 (0x10071569) strips the alpha bit (`and cl,0xfb` at 0x10071579), clears num_trans again (0x10071585) and copies the png_struct's ten-byte background at +0x138 into the info at +0x5a as two dwords and a word (0x1007159a-0x100715a8). PNG_GAMMA 0x2000 moves the gamma word at +0x15c to the info's +0x28 (0x100715c7), PNG_16_TO_8 0x400 halves a depth of exactly 16 (0x100715e2, 0x100715ea), PNG_DITHER 0x40 turns colour type 2 or 6 into a palette, but only with a non-null palette_lookup at +0x1ec and a depth of exactly 8 (0x10071603, 0x10071610, 0x10071618, 0x10071629, store at 0x10071631), PNG_PACK 4 lifts a depth below 8 (0x1007164d, 0x10071652), PNG_GRAY_TO_RGB 0x4000 sets the colour bit (`or al,2` at 0x1007166c) and PNG_RGB_TO_GRAY clears it (`and dl,0xfd` at 0x10071689) - and that last test is a MASK of two bits, `and eax, 0x600000` at 0x1007167a, where png_do_read_transformations compares the whole word with one constant. The channel count is then rebuilt from whatever colour type survived: 1 for a palette (0x1007169a), 3 when the colour bit is set (0x100716b0), 1 otherwise, plus one more for the alpha bit (0x100716ed) - and PNG_STRIP_ALPHA 0x40000 is applied between those two steps (0x100716cd), so a stripped row never gets the extra channel, while PNG_FILLER 0x8000 adds one to colour type 2 or 0 only (0x1007171b, 0x10071728). Last, PNG_USER_TRANSFORM 0x100000 lets the caller RAISE, never lower, the depth and the channel count from png_struct+0x64 and +0x65 (the two `jge` at 0x1007175d and 0x1007177d). The function closes by recomputing pixel_depth as channels * bit_depth truncated to a byte (0x1007179b, 0x100717a1) and rowbytes as (width * pixel_depth + 7) >> 3 with an unsigned shift (0x100717b1-0x100717b7) - the same two lines png_set_IHDR 0x1007dc70 ends with, minus its overflow test. It writes nothing to the png_struct at all. Reimplemented in `shim/src/re/c3bq.cpp`; path-1 A/B GREEN: png_read_transform_info (32 vectors, 32 distinct results, 32 changing state, `log/diff/000714c0_jgld_png_read_transform_info.path1.csv`).
