## Purpose
Creates the master-control object, the stage that decides how many passes the compression will take and what each one does, and settles that plan before any data moves. A 0x24-byte object comes from `cinfo->mem->alloc_small(cinfo, JPOOL_IMAGE, 0x24)` (0x004b51e7..0x004b51ef), is stored at cinfo+0x144 (0x004b51f5) and receives its three method pointers — prepare_for_pass 0x004b5810, pass_startup 0x004b5ca0 and finish_pass 0x004b5cd0 — plus a cleared is_last_pass at +0x10 (0x004b51fc..0x004b5210). initial_setup 0x004b52a0 then validates the image parameters and derives the per-component block counts (0x004b5213). A non-null scan_info (cinfo+0xa4, 0x004b5218 / 0x004b5221 / 0x004b5223) hands the caller's script to validate_script 0x004b5470 (0x004b5226), which is what sets progressive_mode; a null one means one sequential scan over everything, so progressive_mode (cinfo+0xdc) is cleared and num_scans (cinfo+0xa0) set to 1 (0x004b5230 / 0x004b5236). A progressive file then forces optimize_coding (cinfo+0xb0) on (0x004b5240 / 0x004b5246 / 0x004b5248), because the default Huffman tables are not usable for it. The first pass_type (master+0x14) follows: transcoding, which feeds coefficients in directly and therefore has no main pass, starts at the Huffman-optimisation pass 1 when optimize_coding is on and at the output pass 2 when it is off, and a normal compression always starts at the main pass 0 (0x004b5252 / 0x004b5256 / 0x004b525e / 0x004b5260 / 0x004b5269 / 0x004b5272). scan_number (master+0x20) and pass_number (master+0x18) start at zero (0x004b5275 / 0x004b5278) and total_passes (master+0x1c) is num_scans doubled when optimize_coding is on, one optimisation pass plus one output pass per scan, and num_scans otherwise (0x004b527b / 0x004b5281 / 0x004b5289 / 0x004b5292).
