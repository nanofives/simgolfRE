## Purpose
Draws a clipped Bresenham line on an 8-bit surface in a two-colour dash pattern, len1 pixels of c1 then len2 of c2, repeating, starting at the given phase, with the value -1 in either colour meaning "leave these pixels alone". The frame is line8's: x1 == x2 goes to dashedVLine8 0x10011880 (0x100108b8) and y1 == y2 to dashedHLine8 0x100114e0 (0x100108ed), both with all eight remaining arguments; x2 < x1 swaps the two endpoints (0x100108ff..0x1001090e) and with them the two run lengths (0x10010911, three xors), the two colours (0x1001092c, three xors) and the phase, which becomes len1 + len2 - phase (0x10010947); lockBits() of slot +0x10 returning NULL ends the call with nothing released (0x10010969); getClipRect of slot +0xc8 copies the clip rectangle (0x1001097e); and the whole body leaves through one `unlock(1)` at 0x10011216, reached by fourteen forward-goto stubs (0x1001122e..0x10011248). What is new is the dash cursor, set up between getClipRect and the octants: the phase is reduced modulo len1 + len2 by the SIGNED `idiv` at 0x10010995 (so len1 + len2 must not be zero, and a negative phase stays negative), a phase at or past len1 becomes len2 - (phase - len1) and a phase below len1 becomes -(len1 - phase) (0x100109a0 with the two arms at 0x100109a2 and 0x100109b6), and len1 is then negated (0x100109ca). The cursor is negative inside a c1 run and non-negative inside a c2 run. The four octants are line8's, split by y1 < y2 (0x100109e7) and dx >= dy (0x10010a18 downward, 0x10010e36 upward, the upward half taking the CRT abs 0x1007f370 of dy first at 0x10010e25), with the same guards (0x100109f3..0x10010a0b, 0x10010e02..0x10010e1a), the same pre-walks, the same endpoint clamps and the base from slot +0x18 (0x10010aa2, 0x10010c86, 0x10010ec0, 0x100110a5). Each octant writes twice, once before its main loop and once per step inside it, and all eight write sites hold the same block: a negative cursor writes c1 unless c1 is -1 (0x10010add and its seven twins) and then counts up, reloading the cursor with len2 when it reaches zero (0x10010af4 and twins); a non-negative cursor writes c2 unless c2 is -1 (0x10010b02 and twins) and then counts down, reloading it with the negated len1 at zero (0x10010b19 and twins). Unlike dashedHLine16 0xcf90, which masks both colours to 16 bits before testing them against -1 and so can never see one, this function tests the arguments as they came in, so -1 really does leave a gap.
